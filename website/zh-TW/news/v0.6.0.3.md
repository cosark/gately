# Gately v0.6.0.3 發布

2026 年 10 月 28 日

這是 v0.6.0 系列的修復更新，沒有新功能，用到「公網 Gately → 隧道 → 內網 Gately」鏈路的使用者建議升級。

[下載 v0.6.0.3](/zh-TW/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0.3)

## 經可信 PROXY 來源轉發的 HTTPS

公網 Gately 終止 TLS 後，經 frp tcp 隧道以明文 HTTP 加 PROXY v2 標頭轉給內網 Gately 時，內網 Gately 還原出的訪客是公網位址，先前只信任本機與內網來源的 `X-Forwarded-Proto: https`，於是把這類請求當成明文：簽發者為 `https` 的 [OIDC 身分提供者](/zh-TW/docs/modules/oidc) 把登入、授權與權杖請求跳轉或拒絕，網頁認證、共用使用者、單一登入與分享連結的工作階段 Cookie 也不帶 Secure。

現在經「可信 PROXY 來源」進入的連線帶的 `X-Forwarded-Proto: https` 同樣被採信，並統一用於：

- OIDC 簽發者的 HTTPS 判斷，以及各類工作階段 Cookie 的 Secure 標記；
- 第三方登入回跳位址與轉發認證傳給認證服務的協定；
- 開啟「明文 HTTP 跳轉 HTTPS」的連接埠不再對這類請求跳轉，避免循環跳轉；
- 反代站點開啟「新增 X-Forwarded-*」時向後端如實寫 `X-Forwarded-Proto: https`，後端應用能產生正確的 https 連結。

設定方法見 [OIDC 身分提供者](/zh-TW/docs/modules/oidc) 與 [Web 服務](/zh-TW/docs/modules/web) 文件：公網站點開啟「新增 X-Forwarded-*」和「向後端傳送 PROXY v2」，內網 Gately 的監聽開啟接收 PROXY 協定，並把隧道在本機的來源位址加入可信 PROXY 來源。不可信來源與公網訪客自帶的這個請求標頭仍不被採信。

## 重啟監聽時連接埠被佔用

Web 服務監聽、WebDAV 服務與 HTTP-01 驗證的臨時監聽在剛啟動就停止或重啟時，舊連接埠可能還沒釋放，重新監聽偶發報「連接埠已被佔用」（例如連續兩次儲存監聽設定）。現在停止時同步關閉監聽，重啟後立即可用。

## 升級提示

- Docker 拉取新映像後重建容器；OpenWrt 覆蓋安裝新的 `.apk` / `.ipk`；飛牛在應用中心手動安裝新版 `.fpk`；其他部署方式可在「系統設定」中線上升級。
