# Gately v0.6.0.2 發布

2026 年 10 月 28 日

這是 v0.6.0 系列的修復更新，沒有新功能，建議所有使用者升級。

[下載 v0.6.0.2](/zh-TW/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0.2)

## 飛牛桌面入口的 Web 終端

飛牛原生應用從桌面圖示開啟 Gately 時，[Web 終端](/zh-TW/docs/modules/terminal) 連線本機 Shell、SSH 或 Telnet 會停在「連線中」，隨後報失敗（[#31](https://github.com/wangwanjie/gately/issues/31)）；直接存取 16680 連接埠正常。原因是桌面入口經統一閘道的 Unix Socket 轉發，WebSocket 升級時連線沒能被接管。現在桌面入口與直接存取的行為一致，稽核日誌也只在連線接管成功後記為 101。

## 相對設定目錄下的 File Browser

在程式目錄執行 `./gately`、使用預設的 `data` 設定目錄時，託管的 File Browser 每次啟動都報 `fork/exec data/bin/filebrowser: no such file or directory`。現在設定目錄在啟動時轉為絕對路徑，File Browser、frp、cloudflared、Tailscale 與 Docker Compose 拿到的程式、設定和資料庫路徑都是絕對路徑；模組設定裡填寫的相對程式路徑也照常可用。Docker、飛牛與 OpenWrt 安裝包本來就使用絕對路徑，不受影響。

## 介面回應不再翻譯使用者內容

介面語言不是簡體中文時（包括沒有 `Accept-Language` 請求標頭、使用伺服器語言的腳本），讀取設定的介面會把四個字以上的中文片段替換成譯文，例如監聽備註「由端口转发 SNI 分流…」回傳為「由Port forwarding SNI 分流…」，讀出後原樣儲存就把譯文寫進了設定。現在只翻譯程式產生的說明欄位（錯誤、提示、警告、狀態說明等），名稱、備註、分組、命令、網域、記錄值等使用者填寫的內容原樣回傳；排程任務、DDNS 任務和設定歷史也不再整份翻譯。詳見 [API 參考](/zh-TW/docs/reference/api) 的「回應語言」一節。

## 升級提示

- 先前已被改寫成譯文的備註不會自動恢復，可在「設定歷史」中找回原文後手動改回。
- Docker 拉取新映像後重建容器；OpenWrt 覆蓋安裝新的 `.apk` / `.ipk`；飛牛在應用中心手動安裝新版 `.fpk`；其他部署方式可在「系統設定」中線上升級。
