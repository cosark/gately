# Gately v0.6.0.4 publié

29 octobre 2026

[Télécharger v0.6.0.4](/fr/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0.4)

## Application LuCI pour OpenWrt

Chaque version fournit désormais une application LuCI indépendante de l’architecture, `luci-app-gately_0.6.0.4_openwrt_all.ipk` / `.apk`. Installez-la après Gately et LuCI affiche une page **Services → Gately** :

- voir l’état d’exécution, le PID, la version, la mémoire utilisée, le démarrage automatique, l’adresse d’administration et le répertoire de configuration ;
- démarrer, arrêter et redémarrer le service, et activer ou désactiver le démarrage automatique ;
- ouvrir l’interface d’administration de Gately en un clic, avec l’entrée sécurisée des paramètres globaux déjà incluse dans le lien ; un avertissement s’affiche lorsque l’interface n’écoute que sur la boucle locale ou que « Accès réseau local uniquement » est activé ;
- définir le port de l’interface d’administration. Il est enregistré dans `/etc/config/gately` et remplace uniquement le port de l’adresse d’écoute des paramètres globaux ; un réglage qui n’écoute que sur la boucle locale ou sur une adresse du LAN reste inchangé. Si un conflit de port ou un mauvais port rend l’interface inaccessible, vous pouvez le corriger ici ; laissez-le vide pour suivre les paramètres globaux.

L’application suit la langue de LuCI, prend en charge 10 langues et a été testée sur OpenWrt 24.10 (opkg) et 25.12 (apk). La procédure est décrite dans [Installation · Application LuCI](/fr/docs/guide/install#openwrt-luci).

## Variables des sites de redirection

En plus de `{host}`, la cible d’un site de redirection peut désormais utiliser :

- `{path}` / `{PATH}` et `{args}` / `{Args}` : le chemin et la chaîne de requête de la requête d’origine. Avec « Conserver le chemin » activé, la partie écrite dans la cible n’est plus ajoutée une seconde fois ;
- `{port}`, `{hostAndPort}`, `{domainPartN}`, `{pathPartN}`, `{ClientIP}`, `{RemoteIP}` et `{time}` ;
- `{1}` : la partie correspondant à `*` dans un domaine de site comme `*.example.com` ;
- `{STUN_NomRègle_PORT}` / `_IP` / `_ADDR` : l’adresse publique actuelle d’une règle de [Traversée STUN](/fr/docs/modules/stun). Quand le port change, inutile de modifier le site : la requête suivante va vers le nouveau port. Si la règle est désactivée, n’a pas encore réussi la traversée ou est en cours de nouvelle tentative, le site renvoie 503 et le journal d’exécution en indique la raison.

Par exemple, un `*.example.com` placé derrière un CDN peut rediriger vers `https://{1}.v4.example.com:{STUN_web_PORT}{path}{args}`. L’enregistrement vérifie la cible avec des valeurs d’exemple. À l’exécution, une redirection dont la cible développée n’a pas d’hôte renvoie 503, et un hôte de visiteur contenant des caractères absents des noms de domaine, comme `&`, `=` ou `/`, renvoie 400 : les visiteurs ne sont jamais envoyés vers un autre site. Dans une configuration importée, une redirection utilisant ces variables faisait ignorer tout l’écouteur car l’adresse échouait à la validation ; elle s’importe désormais normalement. Voir [Services Web · Variables de redirection](/fr/docs/modules/web#redirect-vars).

## Utilisateurs partagés et clients OIDC en résumé

Dans « Services Web → Paramètres globaux », les utilisateurs partagés et les clients OIDC s’affichent désormais sur une ligne de résumé chacun. Un utilisateur partagé montre le nom d’utilisateur, l’état du TOTP et du mot de passe, les groupes, le nom affiché, l’e-mail et la remarque. Un client OIDC montre le nom, le type confidentiel ou public, un Client ID copiable, le nombre d’URI de redirection, les utilisateurs autorisés et la remarque ; un nouveau secret non enregistré ou une URI de redirection manquante est signalé à part. Cliquez sur « Modifier » ou « Ajouter » pour changer tous les champs dans une boîte de dialogue ; les modifications ne sont écrites qu’avec « OK » et « Annuler » les abandonne. Le nom d’utilisateur ne peut être ni vide ni en double, et le Client ID est obligatoire et unique.

## Notes de mise à niveau

- Docker : récupérez la nouvelle image et recréez le conteneur. OpenWrt : installez le nouveau `.apk` / `.ipk` par-dessus l’ancien, et installez aussi `luci-app-gately` si vous voulez la page LuCI. fnOS : installez le nouveau `.fpk` dans le Centre d’applications. Les autres installations peuvent être mises à niveau en ligne dans les Paramètres.
