# Gately v0.6.0.3 リリース

2026年10月28日

v0.6.0 シリーズの修正アップデートで、新機能はありません。「公開側 Gately → トンネル → LAN 側 Gately」構成のユーザーにアップグレードをおすすめします。

[v0.6.0.3 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0.3)

## 信頼する PROXY 送信元経由の HTTPS

公開側 Gately が TLS を終端し、frp の tcp トンネルで平文 HTTP と PROXY v2 ヘッダーを LAN 側 Gately に転送すると、LAN 側 Gately が復元する訪問者は公開アドレスになります。これまではローカルと LAN からの `X-Forwarded-Proto: https` だけを信頼していたため、これらのリクエストを平文として扱い、`https` 発行者の [OIDC ID プロバイダー](/ja/docs/modules/oidc) がログイン・認可・トークンのリクエストをリダイレクトまたは拒否し、Web 認証・共有ユーザー・シングルサインオン・共有リンクのセッション Cookie にも Secure が付きませんでした。

「信頼する PROXY 送信元」から入った接続の `X-Forwarded-Proto: https` も採用されるようになり、次の判断に一貫して使われます：

- OIDC 発行者の HTTPS 判定と、各種セッション Cookie の Secure フラグ。
- 外部ログインの戻り先アドレスと、転送認証で認証サービスに渡すプロトコル。
- 「平文 HTTP を HTTPS にリダイレクト」が有効なポートでも、これらのリクエストはリダイレクトせず、ループを防ぎます。
- 「X-Forwarded-* を付与」がオンのリバースプロキシサイトは、バックエンドに `X-Forwarded-Proto: https` を渡し、アプリが正しい https リンクを生成できます。

設定方法は [OIDC ID プロバイダー](/ja/docs/modules/oidc) と [Web サービス](/ja/docs/modules/web) のドキュメントを参照してください。公開側サイトで「X-Forwarded-* を付与」と「バックエンドへ PROXY v2 を送信」をオンにし、LAN 側 Gately のリスナーで PROXY プロトコルの受信を有効にして、トンネルのローカル送信元アドレスを信頼する PROXY 送信元に追加します。信頼していない送信元や公開側の訪問者が付けたこのヘッダーは引き続き採用しません。

## リスナー再起動時のポート使用中エラー

Web サービスのリスナー、WebDAV サービス、HTTP-01 検証用の一時リスナーを起動直後に停止・再起動すると、古いポートがまだ解放されておらず、再リッスンがまれに「address already in use」で失敗することがありました（リスナー設定を続けて 2 回保存した場合など）。停止時にリスナーを同期的に閉じるようにし、再起動後すぐに使えるようになりました。

## アップグレードの注意

- Docker は新しいイメージを pull してコンテナーを作り直してください。OpenWrt は新しい `.apk` / `.ipk` を上書きインストール、fnOS はアプリセンターで新しい `.fpk` をインストールしてください。その他の環境は「システム設定」からオンラインでアップグレードできます。
