# Gately v0.6.0.2 リリース

2026年10月28日

v0.6.0 シリーズの修正アップデートで、新機能はありません。すべてのユーザーにアップグレードをおすすめします。

[v0.6.0.2 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0.2)

## fnOS デスクトップからの Web ターミナル

fnOS アプリをデスクトップアイコンから開くと、[Web ターミナル](/ja/docs/modules/terminal) のローカルシェル、SSH、Telnet が「接続中」のまま止まり、その後失敗していました（[#31](https://github.com/wangwanjie/gately/issues/31)）。ポート 16680 への直接アクセスは正常でした。デスクトップの入口は統合ゲートウェイの Unix ソケットを経由しており、WebSocket のアップグレード時に接続を引き継げていませんでした。現在はデスクトップの入口も直接アクセスと同じように動作し、監査ログは接続の引き継ぎに成功したときだけ 101 を記録します。

## 相対パスの設定ディレクトリでの File Browser

プログラムのディレクトリで `./gately` を実行し、既定の `data` 設定ディレクトリを使うと、管理対象の File Browser が起動のたびに `fork/exec data/bin/filebrowser: no such file or directory` で失敗していました。設定ディレクトリを起動時に絶対パスへ変換するようにしたため、File Browser、frp、cloudflared、Tailscale、Docker Compose にはプログラム・設定・データベースの絶対パスが渡されます。モジュール設定に入力した相対パスのプログラムもそのまま使えます。Docker、fnOS、OpenWrt のパッケージはもともと絶対パスを使っているため影響はありません。

## API レスポンスがユーザーの入力内容を翻訳しなくなりました

簡体字中国語以外の言語（`Accept-Language` ヘッダーがなくサーバーの言語が使われるスクリプトを含む）では、設定を読み取るレスポンスで 4 文字以上の中国語の断片が訳語に置き換えられていました。たとえばリスナーの備考「由端口转发 SNI 分流…」が「由Port forwarding SNI 分流…」として返され、読み取った内容をそのまま保存すると訳語が設定に書き込まれていました。現在は Gately が生成するメッセージ項目（エラー、ヒント、警告、状態の説明など）だけを翻訳し、名前、備考、グループ、コマンド、ドメイン、レコード値などのユーザー入力は保存されたとおりに返します。cron タスク、DDNS タスク、設定履歴も全体を翻訳しなくなりました。詳しくは [API リファレンス](/ja/docs/reference/api) の「レスポンスの言語」を参照してください。

## アップグレードの注意

- すでに訳語に書き換えられた備考は自動では戻りません。「設定履歴」で元の文言を確認して手動で戻してください。
- Docker は新しいイメージを pull してコンテナーを作り直してください。OpenWrt は新しい `.apk` / `.ipk` を上書きインストール、fnOS はアプリセンターで新しい `.fpk` をインストールしてください。その他の環境は「システム設定」からオンラインでアップグレードできます。
