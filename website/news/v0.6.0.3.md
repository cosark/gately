# Gately v0.6.0.3 发布

2026 年 10 月 28 日

这是 v0.6.0 系列的修复更新，没有新功能，用到「公网 Gately → 隧道 → 内网 Gately」链路的用户建议升级。

[下载 v0.6.0.3](/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0.3)

## 经可信 PROXY 来源转发的 HTTPS

公网 Gately 终止 TLS 后，经 frp tcp 隧道以明文 HTTP 加 PROXY v2 头转给内网 Gately 时，内网 Gately 还原出的访客是公网地址，此前只信任本机和内网来源的 `X-Forwarded-Proto: https`，于是把这类请求当成明文：签发者为 `https` 的 [OIDC 身份提供方](/docs/modules/oidc) 把登录、授权和令牌请求跳转或拒绝，网页认证、共享用户、单点登录和分享链接的会话 Cookie 也不带 Secure。

现在经「可信 PROXY 来源」进入的连接带的 `X-Forwarded-Proto: https` 同样被采信，并统一用于：

- OIDC 签发者的 HTTPS 判断，以及各类会话 Cookie 的 Secure 标记；
- 第三方登录回跳地址与转发认证传给认证服务的协议；
- 开启「明文 HTTP 跳转 HTTPS」的端口不再对这类请求跳转，避免循环跳转；
- 反代站点开启「添加 X-Forwarded-*」时向后端如实写 `X-Forwarded-Proto: https`，后端应用能生成正确的 https 链接。

配置方法见 [OIDC 身份提供方](/docs/modules/oidc) 与 [Web 服务](/docs/modules/web) 文档：公网站点开启「添加 X-Forwarded-*」和「向后端发送 PROXY v2」，内网 Gately 的监听开启接收 PROXY 协议，并把隧道在本机的来源地址加入可信 PROXY 来源。不可信来源与公网访客自带的这个请求头仍不被采信。

## 重启监听时端口被占用

Web 服务监听、WebDAV 服务与 HTTP-01 验证的临时监听在刚启动就停止或重启时，旧端口可能还没释放，重新监听偶发报「端口已被占用」（例如连续两次保存监听设置）。现在停止时同步关闭监听，重启后立即可用。

## 升级提示

- Docker 拉取新镜像后重建容器；OpenWrt 覆盖安装新的 `.apk` / `.ipk`；飞牛在应用中心手动安装新版 `.fpk`；其他部署方式可在「系统设置」中在线升级。
