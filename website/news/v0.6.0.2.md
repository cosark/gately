# Gately v0.6.0.2 发布

2026 年 10 月 28 日

这是 v0.6.0 系列的修复更新，没有新功能，建议所有用户升级。

[下载 v0.6.0.2](/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0.2)

## 飞牛桌面入口的 Web 终端

飞牛原生应用从桌面图标打开 Gately 时，[Web 终端](/docs/modules/terminal) 连接本机 Shell、SSH 或 Telnet 会停在「连接中」，随后报失败（[#31](https://github.com/wangwanjie/gately/issues/31)）；直接访问 16680 端口正常。原因是桌面入口经统一网关的 Unix Socket 转发，WebSocket 升级时连接没能被接管。现在桌面入口与直接访问的行为一致，审计日志也只在连接接管成功后记为 101。

## 相对配置目录下的 File Browser

在程序目录执行 `./gately`、使用默认的 `data` 配置目录时，托管的 File Browser 每次启动都报 `fork/exec data/bin/filebrowser: no such file or directory`。现在配置目录在启动时转为绝对路径，File Browser、frp、cloudflared、Tailscale 与 Docker Compose 拿到的程序、配置和数据库路径都是绝对路径；模块设置里填写的相对程序路径也照常可用。Docker、飞牛与 OpenWrt 安装包本来就使用绝对路径，不受影响。

## 接口响应不再翻译用户内容

界面语言不是简体中文时（包括没有 `Accept-Language` 请求头、使用服务端语言的脚本），读取配置的接口会把四个字以上的中文片段替换成译文，例如监听备注「由端口转发 SNI 分流…」返回为「由Port forwarding SNI 分流…」，读出后原样保存就把译文写进了配置。现在只翻译程序生成的说明字段（错误、提示、警告、状态说明等），名称、备注、分组、命令、域名、记录值等用户填写的内容原样返回；计划任务、DDNS 任务和配置历史也不再整份翻译。详见 [API 参考](/docs/reference/api) 的「响应语言」一节。

## 升级提示

- 此前已被改写成译文的备注不会自动恢复，可在「配置历史」中找回原文后手动改回。
- Docker 拉取新镜像后重建容器；OpenWrt 覆盖安装新的 `.apk` / `.ipk`；飞牛在应用中心手动安装新版 `.fpk`；其他部署方式可在「系统设置」中在线升级。
