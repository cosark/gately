# Gately v0.6.0.2 출시

2026년 10월 28일

v0.6.0 시리즈의 버그 수정 업데이트로, 새 기능은 없습니다. 모든 사용자에게 업그레이드를 권장합니다.

[v0.6.0.2 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0.2)

## fnOS 데스크톱의 웹 터미널

fnOS 앱을 데스크톱 아이콘으로 열면 [웹 터미널](/ko/docs/modules/terminal)의 로컬 셸, SSH, Telnet 연결이 "연결 중"에서 멈춘 뒤 실패했습니다([#31](https://github.com/wangwanjie/gately/issues/31)). 16680 포트로 직접 접속하면 정상이었습니다. 데스크톱 진입점은 통합 게이트웨이의 Unix 소켓을 거치는데, WebSocket 업그레이드 시 연결을 넘겨받지 못했습니다. 이제 데스크톱 진입점도 직접 접속과 똑같이 동작하며, 감사 로그는 연결을 넘겨받은 뒤에만 101로 기록합니다.

## 상대 경로 설정 디렉터리의 File Browser

프로그램 디렉터리에서 `./gately`를 실행하고 기본 `data` 설정 디렉터리를 쓰면 관리되는 File Browser가 시작할 때마다 `fork/exec data/bin/filebrowser: no such file or directory`로 실패했습니다. 이제 설정 디렉터리를 시작 시 절대 경로로 바꾸므로 File Browser, frp, cloudflared, Tailscale, Docker Compose가 프로그램·설정·데이터베이스의 절대 경로를 받습니다. 모듈 설정에 입력한 상대 프로그램 경로도 그대로 동작합니다. Docker, fnOS, OpenWrt 패키지는 원래 절대 경로를 사용하므로 영향이 없습니다.

## API 응답이 사용자 내용을 번역하지 않음

중국어 간체 이외의 언어(`Accept-Language` 헤더 없이 서버 언어를 쓰는 스크립트 포함)에서는 설정을 읽는 응답이 4자 이상의 중국어 조각을 번역어로 바꿨습니다. 예를 들어 리스너 비고 「由端口转发 SNI 分流…」가 「由Port forwarding SNI 分流…」로 반환되어, 읽은 내용을 그대로 저장하면 번역어가 설정에 기록되었습니다. 이제 Gately가 생성한 메시지 필드(오류, 힌트, 경고, 상태 설명 등)만 번역하고, 이름, 비고, 그룹, 명령, 도메인, 레코드 값 등 사용자가 입력한 내용은 저장된 그대로 반환합니다. cron 작업, DDNS 작업, 설정 기록도 더 이상 통째로 번역하지 않습니다. 자세한 내용은 [API 참조](/ko/docs/reference/api)의 "응답 언어"를 참고하세요.

## 업그레이드 안내

- 이미 번역어로 바뀐 비고는 자동으로 복원되지 않습니다. "설정 기록"에서 원래 문구를 찾아 직접 되돌리세요.
- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만드세요. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치하고, fnOS는 앱 센터에서 새 `.fpk`를 설치하세요. 그 밖의 설치 방식은 "시스템 설정"에서 온라인 업그레이드할 수 있습니다.
