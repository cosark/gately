# Gately v0.6.0.3 출시

2026년 10월 28일

v0.6.0 시리즈의 버그 수정 업데이트로, 새 기능은 없습니다. "공인 Gately → 터널 → 내부망 Gately" 구성을 쓰는 사용자에게 업그레이드를 권장합니다.

[v0.6.0.3 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0.3)

## 신뢰할 PROXY 출처를 거친 HTTPS

공인 Gately가 TLS를 종료하고 frp tcp 터널로 평문 HTTP와 PROXY v2 헤더를 내부망 Gately에 전달하면, 내부망 Gately가 복원한 방문자는 공인 주소가 됩니다. 이전에는 로컬과 내부망에서 온 `X-Forwarded-Proto: https`만 신뢰했기 때문에 이런 요청을 평문으로 처리했습니다. 그래서 발급자가 `https`인 [OIDC 아이덴티티 공급자](/ko/docs/modules/oidc)가 로그인·인가·토큰 요청을 리디렉션하거나 거부했고, 웹 인증·공유 사용자·싱글 사인온·공유 링크의 세션 쿠키에도 Secure가 붙지 않았습니다.

이제 "신뢰할 PROXY 출처"에서 들어온 연결의 `X-Forwarded-Proto: https`도 신뢰하며, 다음 판단에 일관되게 사용합니다.

- OIDC 발급자의 HTTPS 판단과 각종 세션 쿠키의 Secure 플래그
- 외부 로그인 복귀 주소와 전달 인증에서 인증 서비스에 넘기는 프로토콜
- "평문 HTTP를 HTTPS로 리디렉션"이 켜진 포트에서도 이런 요청은 리디렉션하지 않아 반복 리디렉션을 막습니다
- "X-Forwarded-* 추가"를 켠 리버스 프록시 사이트는 백엔드에 `X-Forwarded-Proto: https`를 전달해, 백엔드 앱이 올바른 https 링크를 만듭니다

설정 방법은 [OIDC 아이덴티티 공급자](/ko/docs/modules/oidc)와 [웹 서비스](/ko/docs/modules/web) 문서를 참고하세요. 공인 사이트에서 "X-Forwarded-* 추가"와 "백엔드에 PROXY v2 전송"을 켜고, 내부망 Gately의 리스너에서 PROXY 프로토콜 수신을 켠 뒤 터널의 로컬 출처 주소를 신뢰할 PROXY 출처에 추가합니다. 신뢰하지 않는 출처와 공인 방문자가 보낸 이 헤더는 계속 무시합니다.

## 리스너 재시작 시 포트 사용 중 오류

웹 서비스 리스너, WebDAV 서비스, HTTP-01 검증용 임시 리스너를 시작 직후 중지하거나 재시작하면 이전 포트가 아직 해제되지 않아 다시 수신할 때 가끔 "address already in use" 오류가 났습니다(예: 리스너 설정을 연달아 두 번 저장). 이제 중지할 때 리스너를 동기적으로 닫아 재시작 후 바로 사용할 수 있습니다.

## 업그레이드 안내

- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만드세요. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치하고, fnOS는 앱 센터에서 새 `.fpk`를 설치하세요. 그 밖의 설치 방식은 "시스템 설정"에서 온라인 업그레이드할 수 있습니다.
