# 동적 DNS (DDNS)

가정용 인터넷 회선의 공인 IP는 바뀌곤 합니다. DDNS는 IP가 바뀌면 DNS 레코드를 자동으로 갱신하여 도메인이 항상 현재 주소를 가리키게 합니다.

## 지원하는 제공자

Alibaba Cloud, Cloudflare, Tencent Cloud, DNSPod, Huawei Cloud, GoDaddy, Porkbun, dynv6, DuckDNS, Amazon Route 53, OVHcloud, Gandi, NS1, Bunny DNS, Namecheap, DynDNS2, 그리고 사용자 정의 콜백(내장되지 않은 제공자나 자체 구축한 API용)을 지원합니다.

| 제공자 | 자격 증명 | 인증서 DNS 검증에 사용 가능 |
| --- | --- | --- |
| Amazon Route 53 | Access Key ID / Secret Access Key, 선택적으로 호스팅 영역 ID | 예 |
| OVHcloud | Application Key / Secret과 Consumer Key, 엔드포인트 ovh-eu / ovh-ca / ovh-us | 예 |
| Gandi | Personal Access Token | 예 |
| NS1 | API Key | 예 |
| Bunny DNS | Account API Key | 예 |
| Namecheap | 도메인의 Dynamic DNS 비밀번호(A 레코드만) | 아니요 |
| DynDNS2 | 사용자 이름, 비밀번호, 업데이트 주소. No-IP, Dynu 등 dyndns2 프로토콜 호환 서비스에 사용 | 아니요 |

## IP를 가져오는 방법

- **URL**: 공인 IP 조회 주소를 요청합니다(원하는 서비스로 바꾸거나 직접 구축할 수 있습니다).
- **네트워크 인터페이스**: 지정한 인터페이스의 주소를 직접 읽습니다. 공인 IP를 가진 장치에 적합합니다.
- **명령어**: 명령을 실행해 그 출력을 사용합니다. 특수한 네트워크 환경에 적합합니다.

IPv4와 IPv6를 지원합니다.

## 알림

IP가 바뀌거나 동기화에 실패하면 Webhook을 호출할 수 있습니다.

## 사용 권장 사항

- DNS 제공자에서는 레코드 편집 권한만 있는 하위 계정 키를 만들어 사용하고, 주 계정 키는 쓰지 마세요.
- 작업을 새로 만든 뒤 「강제 동기화」를 눌러 레코드가 갱신되었는지 확인하세요.
- 공인 IP 조회 주소는 프로젝트 측 서비스에 의존하지 않으며 작업에서 언제든 바꿀 수 있습니다.

## 그룹과 정렬

작업에 "그룹"(최대 64자)을 지정할 수 있습니다. 목록은 그룹별로 접을 수 있는 구역으로 표시되며, 그룹은 처음 나타난 순서대로, 그룹이 없는 작업은 맨 뒤에 놓입니다. 접힘 상태는 브라우저에 저장됩니다. 페이지 상단의 검색 상자로 이름, 그룹, 도메인 또는 제공업체을(를) 기준으로 거를 수 있습니다.

"정렬"을 눌러 정렬 모드로 들어갑니다. 화살표로 작업을 위아래로 옮기거나 그룹 전체를 옮길 수 있습니다. 여러 작업을 선택한 뒤 그중 하나를 끌면 함께 이동하고, 다른 그룹의 작업이나 그룹 제목에 놓으면 그 그룹으로 들어갑니다. 도구 모음에서 선택한 작업을 지정한 그룹으로 한 번에 옮길 수 있고, 이름을 비우면 그룹에서 뺍니다. 순서와 그룹은 목록 표시에만 영향을 주며, 바꿔도 작업은 다시 시작되지 않습니다.

그룹 제목에 마우스를 올리고 연필 버튼을 누르면 그룹 이름을 바꿀 수 있습니다. 그룹의 항목도 함께 새 이름으로 바뀌며 위치와 순서는 그대로입니다. 이미 있는 그룹 이름을 고르면 확인 후 두 그룹이 합쳐집니다.
