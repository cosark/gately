# STUN 통과

통신사가 고정 공인 포트를 제공하지 않을 때, STUN 통과는 NAT 홀 펀칭으로 공인 매핑 주소와 포트를 얻어 외부에서 내부 서비스에 접속할 수 있게 합니다.

## 기능

- TCP / UDP 통과와 연결 유지
- UPnP / NAT-PMP로 라우터에 포트 매핑을 자동 생성
- 내장 포워딩: 통과로 얻은 공인 포트를 내부 대상으로 바로 전달
- 공인 주소나 포트가 바뀌면 Webhook과 스크립트를 실행하며 DNS 갱신이나 클라이언트 알림 등에 활용할 수 있습니다

## 함께 쓰기

STUN으로 얻은 공인 포트는 보통 바뀌므로 다음과 함께 쓰기를 권장합니다.

- [동적 DNS](/ko/docs/modules/ddns) 또는 Webhook / 스크립트로 새 주소를 DNS에 동기화
- [웹 서비스](/ko/docs/modules/web)로 HTTPS 진입점 제공
- 웹 서비스의 리다이렉트 사이트에서 `{STUN_규칙이름_PORT}` 등의 변수로 규칙의 현재 공인 주소를 참조할 수 있으며, 포트가 바뀌면 자동으로 새 포트로 이동합니다. [리다이렉트 변수](/ko/docs/modules/web#redirect-vars) 참고.

## 제약

라우터 WAN 포트가 통신사급 NAT(`100.64.0.0/10`) 뒤에 있으면 외부에서 통과 포트에 접근할 수 없으며, 이는 네트워크 환경 자체의 제약입니다. 이 경우 [Tailscale, frp, Cloudflare 터널](/ko/docs/modules/tunnels)을 대신 사용할 수 있습니다.

## 배포 팁

STUN은 호스트 포트를 직접 수신해야 하므로 Docker 배포에서는 `--network host`를 권장합니다.
